# Conformance corpus

Fixtures and expected output that **all three platform builds test against**,
so "did that finding actually reach Pebble?" is a question a test run answers
in seconds rather than one somebody has to remember to ask.

## Why it exists

The three implementations cannot share code — ES5 PKJS + Moddable XS,
Kotlin/JVM and browser TypeScript — but the rules they implement are the same,
and the bugs that have actually shipped were all in that shared part. A shared
fixture set is the only mechanism that catches those mechanically. See
[`../PLAN.md`](../PLAN.md) §5.

## What is in here

| Path | Pins |
|---|---|
| `timeline/synthetic.bif` + `.expected.json` | Trick-play index parsing: header multiplier, sentinel-derived last-frame length, the size invariant, byte-identical duplicate detection, and the malformed inputs that must throw. |
| `subs/torture.srt` + `.expected.json` | SRT parsing and cleaning, empty-cue dropping, and cue-to-window ownership. |
| `scene/episode.{frames,cues,expected}.json` | Scene selection at scale — blank filtering, duplicate skipping, native-timing vs fixed-interval binning, empty-scene removal. |
| `cues/layout.cases.json` | Cue wrapping and pagination: no word is ever lost. |

## Nothing here is copyrightable

Deliberately. `scene/episode.frames.json` is **frame timings and byte lengths**
— no image bytes. `scene/episode.cues.json` is **cue timings** — no dialogue.
`timeline/synthetic.bif` contains generated byte patterns, not JPEGs.
`subs/torture.srt` is written for this corpus.

That is enough to pin every behaviour worth pinning, and it means the corpus
can live in the public platform repos.

`scene/episode.*` is a synthetic mirror of the episode [[F-001]] was measured
against, tuned to reproduce its shape:

| | Fixture | Real episode (F-001) |
|---|---|---|
| Frames | 1815 | 1815 |
| Byte-identical duplicates | 78.7% | 80.8% |
| Cues | 569 | 586 |
| Track size | 9.94 MB | 9.99 MB |
| Scenes after dedup + empty drop | 217 | 222 |
| Bytes shipped | 1.18 MB | 1.19 MB |

## The expectations are not generated from the implementation

This is the part that makes the corpus worth anything.

`tools/corpus/make-corpus.js` writes the expected values **from the rules** —
by hand for the small fixtures, and for `scene/` via a second implementation
of the selection policy that shares no code with
`tools/timeline-tuner/lib/scenes.js`.

Had the expectations been produced by running the reference implementation,
the corpus would pin whatever that implementation currently does, including
its bugs, and every runner would agree with it forever. Instead a
disagreement means one of the two is wrong, and finding out which is the
point.

It works: the first run of `check-corpus.js` reported three failures, all the
same root cause, and the reference implementation was the one that was wrong.
That is [[F-003]].

## Running it

```bash
node tools/corpus/check-corpus.js    # reference implementation
node tools/corpus/make-corpus.js     # regenerate fixtures (deterministic)
```

`make-corpus.js` is deterministic — a fixed LCG, no `Math.random`, no clock.
A diff after running it means a rule changed, not that the generator wandered.

Each platform repo has its own runner over a vendored copy of these fixtures;
`tools/corpus/sync-corpus.sh` pushes the copies out and flags drift.

## Adding a fixture

1. Add the rule to `findings/` first, with its platform table filled in.
2. Add the fixture and its expectation to `make-corpus.js`, deriving the
   expectation from the rule rather than from any code.
3. Add the assertion to `check-corpus.js` and to each platform runner.
4. Point the finding's **Conformance** line at the fixture.
